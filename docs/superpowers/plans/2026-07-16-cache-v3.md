# Cache v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the cache to one file per site behind a swappable storage interface, and make a deadline (or any digit) change on a real content line trigger a re-extraction.

**Architecture:** The per-line stable key gains a digit-inclusive content hash (`keyHashes` replaces `stableKeys`); `diff` reports `changedKeys` (same key, hash moved) alongside added/removed. Persistence splits into `lib/storage.js` (one `cache/<md5(url)>.json` per site); `lib/cache.js` becomes schema-only; `main.js` loads/saves per site instead of holding one in-memory cache object.

**Tech Stack:** Node.js (CommonJS), `node:test`, Node's built-in `crypto` (stdlib — **not** a dependency). No new packages.

**Spec:** `docs/superpowers/specs/2026-07-16-cache-v3-design.md` (commit `3f27b34`)

## Global Constraints

- **CommonJS only.** `require`/`module.exports`. No ESM.
- **No new dependencies.** `crypto`, `fs`, `path`, `os` are all Node stdlib.
- **`npm test` must stay offline and zero-token.** Never calls Gemini or the network.
- **Never run `node main.js`** — it drives 14 live sites, spends real tokens, and POSTs to the production webhook. Verify with `node --check main.js` + `npm test` only.
- **Hebrew unicode ranges in regexes MUST be escape sequences** (`֐-׿`), never literal characters. Hebrew in plain strings (`'אין'`) is fine.
- **`lib/` modules are pure** except `lib/ai.js` and the new `lib/storage.js` (file I/O).
- **The cache stores RAW merged tenders**, never the validated list. Every `makeSiteEntry` call takes `merged` (or `siteEntry.tenders` / `[]`) as its tenders argument — never `kept`. (Phase 1 invariant: degrading a number to `"אין"` in the cache would flip its `upsertKey` from `num:` to `title:` and duplicate it next run.)
- **Save-before-deliver preserved:** the cache record is written (with `pendingDelivery: true`) before the webhook POST, flipped to `false` on HTTP 200.
- **Webhook contract unchanged:** `POST { tenders: [...] }` with `x-webhook-key`.
- **Migration is not a step:** `getSiteEntry` returns `null` for any non-v3 record and `loadRaw` returns `null` for a site with no file yet — both route the site through full-extraction-then-save-v3. All 14 sites re-extract once on the first v3 run (~2¢, expected).

## ⚠️ Tasks 3, 4, 5 MUST land as ONE commit

Task 3 changes `diff`/`isDiffTooLarge` signatures and Task 4 changes `getSiteEntry`/`makeSiteEntry` and removes `loadCache`/`saveCache` — both leave `main.js` calling functions with the wrong shape. `main.js` is **runtime-broken** until Task 5 rewires it, and `node --check` does NOT catch this (it only parses; undefined-at-runtime calls pass). `npm test` also stays green because no test imports `main.js`. // Content hash per stable key: md5 of the digit-INCLUSIVE lines that map to
// that key, sorted so collision order does not matter. This is the signal that
// a number (e.g. a deadline) changed under an otherwise-identical line. Noise
// lines (key === null) are excluded — they are never diffed.
function buildKeyHashes(entries) {
  const linesByKey = new Map();
  for (const e of entries) {
    if (e.key === null) continue;
    if (!linesByKey.has(e.key)) linesByKey.set(e.key, []);
    linesByKey.get(e.key).push(e.line);
  }
  const out = {};
  for (const [key, lines] of linesByKey) {
    const joined = lines.slice().sort().join('\n');
    out[key] = crypto.createHash('md5').update(joined).digest('hex');
  }
  return out;
}
```

const fs = require('fs');
const path = require('path');
const crypto = require('crypto');

const CACHE_DIR = path.join(__dirname, '..', 'cache');

function fileFor(url, dir) {
  const hash = crypto.createHash('md5').update(url).digest('hex');
  return path.join(dir, `${hash}.json`);
}

// Per-site persistence. Swappable: an S3/DB backend implements the same
// loadRaw/saveRaw pair. Returns the parsed object (including its url) or null
// when absent or unreadable — callers treat null as "run the full-extraction
// path", exactly like a missing/legacy cache entry.
function loadRaw(url, dir = CACHE_DIR) {
  const file = fileFor(url, dir);
  try {
    if (!fs.existsSync(file)) return null;
    return JSON.parse(fs.readFileSync(file, 'utf8'));
  } catch (e) {
    return null;
  }
}

function saveRaw(url, obj, dir = CACHE_DIR) {
  fs.mkdirSync(dir, { recursive: true });
  fs.writeFileSync(fileFor(url, dir), JSON.stringify({ url, ...obj }, null, 2), 'utf8');
}

module.exports = { loadRaw, saveRaw, CACHE_DIR };
```

function isDiffTooLarge(addedKeys, removedKeys, changedKeys, cachedCount, newCount) {

```js
// Schema for a v3 per-site cache record. Persistence lives in lib/storage.js.

function makeSiteEntry(keyHashes, tenders, pendingDelivery) {
  return {
    version: 3,
    keyHashes,
    tenders,
    pendingDelivery,
    updatedAt: new Date().toISOString()
  };
}

// Validates one raw record loaded from storage. Returns it when it is a usable
// v3 entry, else null — which routes the site down the full-extraction path.
// This is also the v2/legacy migration: any non-v3 record re-extracts once and
// is re-saved as v3. There is no separate migration step.
function getSiteEntry(raw) {
  if (!raw || typeof raw !== 'object' || raw.version !== 3) return null;
  if (typeof raw.keyHashes !== 'object' || raw.keyHashes === null || Array.isArray(raw.keyHashes)) return null;
  if (!Array.isArray(raw.tenders)) return null;
  return raw;
}

module.exports = { makeSiteEntry, getSiteEntry };
```
